## Data bug fixed: white-background convention, dataset reprocessed (2026-08-01)

**Bug:** `prepare_dataset.py`'s `flatten_to_black()` assumed alpha correctly encodes tissue-cutout transparency and alpha-composited every crop onto black on that assumption. A subset of source crops instead delimit tissue via an **opaque white background** (alpha=255 everywhere) — the exact same source-data convention issue the segmentation phase independently discovered and fixed (root `CLAUDE.md` Sec 1.4.4). Since classification's pipeline is a deliberate from-scratch reimplementation (isolation rule), it never received an equivalent fix — alpha-compositing a fully-opaque image is a no-op, so the white background passed straight through into the processed `.jpg` unchanged.

**Discovered:** 2026-08-01, while building the Grad-CAM tissue-attention-ratio diagnostic (`gradcam_analysis.ipynb`) — a naive black-threshold tissue mask would have silently mis-measured a chunk of the Italy baseline group. A full scan confirmed **30/211 forniceal_palpebral patients affected — 30/116 (25.9%) of Italy, 0/95 (0%) of India.** A country-correlated background-color artifact this strong and this cleanly split is exactly the kind of shortcut-learning risk this whole investigation has been trying to pin down.

**Fix:** ported `Segmentation/scripts/build_aligned_dataset.py`'s already-validated `_alpha_is_functional()` detection logic verbatim (same thresholds: `ALPHA_THRESHOLD=127`, `OPAQUE_ALPHA_FRACTION_THRESHOLD=0.99`, `WHITE_BACKGROUND_THRESHOLD=245`) into `flatten_to_black()`. Per-crop, automatic: if alpha's opaque fraction is ≥0.99 (near-uniformly opaque — carries no real shape info), falls back to a near-white RGB threshold instead of alpha-compositing. Not a hardcoded patient list.

**Verified, not just written:**
1. Targeted test on the known-affected `Italy_012` (forniceal_palpebral): source alpha confirmed 100% opaque (`_alpha_is_functional` → `False`), fixed output has 0.0% near-white pixels (down from a white background covering most of the canvas), all 4 corners pure black. Visual before/after comparison confirmed the tissue crop itself is pixel-identical — only the background changed.
2. Full reprocessing re-run (`prepare_dataset.py` `main()`, both tissue types, all 217 patients) — `metadata.csv`, `splits.csv`, `extraction_log.csv` diffed byte-identical before vs. after, confirming the fix touched only image pixels, not labels/splits/inclusion logic. Extraction counts unchanged (217 palpebral, 211 forniceal_palpebral).
3. Full-dataset validation scan post-reprocess: **0/211 forniceal_palpebral and 0/217 palpebral patients flagged (two independent checks: near-white-fraction threshold and explicit corner-pixel check). Max near-white fraction across all 211 forniceal_palpebral patients: 0.0005** (residual specular highlights within tissue itself, not background).

**Consequence — every existing classification result was trained on the pre-fix (buggy) images:** the original 6-combo run, the 18-combo v2 sweep (batches 1+2), and the 5-fold CV run all used images with this white-background artifact present for ~26% of Italy patients. None of those results are invalidated as measurements of what was actually trained, but **none of them benefit from this fix either** — retraining against the corrected images is required to find out whether/how much this bug was contributing to the India/Italy AUC gap and the model's apparent reliance on non-tissue cues. Not yet done.

**Not yet decided:** whether to re-run the full 18-combo sweep, just the 5-fold CV, or something smaller first, against the corrected data.

## 5-Fold CV run complete and analyzed (2026-08-01)

Real 5-fold/150-epoch Kaggle run for `efficientnet_b0_forniceal_palpebral_cv` (locked hyperparameters from Batch-1 trial #9, no Optuna) is done — project author placed results in `classification/datapreparepipeline/efficientnet_b0_forniceal_5fold_cv/outputs/{checkpoints,logs,plots}/`. Full analysis, all numbers computed directly from the 5 `*_fold{N}_history.json` files and `*_cv_summary.json` (not estimated): **`classification/datapreparepipeline/efficientnet_b0_forniceal_5fold_cv/outputs/CV_5FOLD_ANALYSIS_REPORT.md`**.

**Headline results (mean ± SD across 5 folds, all early-stopped between epoch 37-69, none hit the 150-epoch ceiling):**
- Overall: F1 = 0.867±0.053, AUC = 0.876±0.066, Balanced Accuracy = 0.884±0.053.
- **India AUC = 0.639±0.057 (range 0.564-0.729)** — every fold underperforms the single-split Optuna result this run was meant to validate (India AUC 0.750, `efficientnet_b0_forniceal_palpebral_v2_study_summary.json`). **This CV mean, not the single-split number, is now the number to cite for India-cohort claims going forward.**
- Italy AUC = 0.922±0.098 (high variance — one fold, #4, drops to 0.767).

**Strongest new finding of this run (not visible in any single-split result): India recall/sensitivity is exactly 1.000 in all 5 independent folds — 0 false negatives across all 57 India-anemic validation patients, 5 differently-initialized models, 5 different splits.** Combined with India specificity of only 0.35±0.11 and near-constant per-fold `pos_weight` (1.31-1.37, ruling out fold-specific hyperparameter noise as the cause), this is strong, reproducible evidence of a near-deterministic "predict anemic for India" shortcut rather than genuine per-patient discrimination — the clearest version yet of the country-shortcut pattern already documented across the original 6-combo and 18-combo v2 comparisons, now shown to survive 5 independent re-trainings rather than being one split's artifact.

**Overfitting analysis (folds 1 and 4, contrasted with fold 2 as the healthy baseline):** both project-author-flagged folds confirmed as real via exact replay of the early-stopping/`ReduceLROnPlateau` state machine against each fold's logged `val_loss_history`/`lr_history` (reconstructed stop epoch matched logged `n_epochs_run` in all 5 folds, cross-validating the analysis). Fold 4: sharp overfit, last val-loss improvement at epoch 22 (worst best-case val loss of any fold, 0.605), final train/val gap +0.145 (largest of all 5), 3 LR halvings none of which recovered generalization. Fold 1: milder/slower version, last improvement at epoch 23, final gap +0.071 (about half of fold 4's). Folds 2/3/5 show no divergence at all — val loss tracks at or below train loss throughout, consistent with the expected train-augmented/val-clean asymmetry (`HorizontalFlip`+`Rotate` on train only), not leakage. Root cause: per-fold train/val split composition (small-N k-fold variance on a 178-patient pool), not the fixed hyperparameters — same LR/WD/dropout produces clean convergence on 3 of 5 folds.

**Nuance on the AUC gap specifically:** fold 4 has the worst India AUC but *not* the worst India/Italy gap (0.203) — Italy AUC also collapses in that fold (0.767), so it's a generally hard split, not an India-specific amplifier. The starkest relative disparities are folds 3 and 5 (Italy AUC = 1.000 exactly, India AUC = 0.600/0.636) — cases where the aggregate metric (F1 ~0.88, AUC ~0.90-0.91) looks strong and would mask the India-specific shortfall if the country breakdown weren't checked.

**Latency (not tracked by the training pipeline — measured locally for this report, RTX 4050):** batch=1 GPU 13.9ms mean / CPU 26.6ms mean; batch=32 throughput ≈663 img/sec (1.5ms/image amortized). Identical across all 5 folds by construction (same architecture, only weights differ) — not a per-fold-varying metric. Not a deployment concern at this latency.

**Mitigation strategies identified for the India AUC problem (full detail + rationale in the report), ranked by recommended investigation order:** (0) Grad-CAM/saliency inspection on India false positives to directly test the shortcut-learning hypothesis before investing in fixes; (data-centric) country-balanced mini-batch sampling, HSV+CLAHE illumination normalization (literature-backed, `04_literature_review_findings.md`), more India data; (algorithmic) domain-adversarial training (DANN-style, most direct answer to "unlearn the shortcut"), Group-DRO/worst-group loss, within-dataset CORAL (already flagged as untested in the literature review), partial backbone fine-tuning with stronger regularization; (cheap/stopgap) per-country post-hoc threshold recalibration — explicitly flagged as not a fix for the AUC/discrimination problem itself, since AUC is threshold-independent. **None implemented yet — this is a menu of options, not a decision.**

**Not yet done:** deciding which mitigation strategy (if any) to pursue next; any decision on whether the CV mean or the original single-split result gets reported as "the" Phase 4 headline result in the thesis (recommendation above: CV mean, especially for India-cohort claims, precisely because this run demonstrated the single-split number doesn't reliably replicate).

Confirmed empirically (not just reasoned about) that the shared modules resolve to the correct shared files with no collision.

**Confirmed final decisions (this session):**
1. **Fresh, randomly-initialized head per fold, no warm-start** from `best_efficientnet_b0_forniceal_palpebral_v2.pth` — resolves the initialization-leakage concern raised earlier (that checkpoint's weights were selected via its own validation F1 on the *original* split, which could partially overlap with any given fold's training data). `build_efficientnet_b0()` (reused from the shared engine) already does this correctly — every call constructs a fresh random `Dropout -> Linear` head, no checkpoint is ever loaded in `run_fold()`.
2. **Hyperparameters locked from Batch 1 trial #9** (the winner, val F1=0.933), Optuna dropped entirely for this pipeline: `learning_rate=0.0008200518402245837`, `weight_decay=1.9634341572933354e-06`, `dropout_rate=0.2`.
3. **Root cause of the "jagged loss curves" identified empirically, not assumed:** correlated per-trial val-loss volatility against both hyperparameters across all 12 real batch-1 trials. Learning rate correlated at 0.998 (near-perfect); dropout correlated at -0.09 (none). The two most jagged trials were the two highest sampled learning rates, regardless of dropout. - **Hgb distributions genuinely differ by country, not just the derived labels**: India mean 11.47 / median 11.30 vs. Italy mean 13.83 / median 14.10 (n=95, 122). Variance is nearly identical between countries (4.31 vs 4.16) — this is a clean mean shift, not a dispersion difference.

- **Margin analysis (the actual test of "is this threshold-sensitive"):** only 16/95 India patients and 11/122 Italy patients sit within 0.5 g/dL of their own WHO threshold. Mean margin is -1.04 g/dL for India (typical patient sits a full point *below* cutoff) and +1.16 g/dL for Italy (typical patient sits well *above*). Not a borderline-heavy distribution where nudging the threshold would flip many labels — the separation is robust in both directions.
- **Country-specific thresholds were already proposed and explicitly rejected once before** (see the "Two decisions resolved before any code was written" section above) — for exactly the reason this analysis reinforces: the originally-floated thresholds would have raised India's cutoff (India M<14.0 vs the WHO M<13.0 used now), which would have labeled *more* India patients anemic, widening the gap rather than closing it. Flagged this explicitly since the project author's current question re-approaches the same fork; the reasoning against it still holds.
- **More useful lever than the threshold:** the `India_acc`/`Italy_acc` gap is very likely the same systematic pattern already documented across the original 6 models (global `pos_weight` mismatching each country's local class balance) rather than a labeling problem — `balanced_accuracy`/`AUC` (both added in the metrics-enrichment step) are far less distorted by a skewed local class prior than raw accuracy and are the better metric to watch per-country going forward.

## Literature review: threshold formulation & demographic bias (2026-07-28)
Full report: `04_literature_review_findings.md`. Prompted by the same `India_acc`/`Italy_acc` gap investigated above; project author supplied 3 real papers + their own research summary docx from `D:\khaje\EYES-DEFY-ANEMIA\Source\Paper_Eye\` (a directory now `.gitignore`'d, never tracked — see the new git-security rule in `CLAUDE.md`/`03_tech_stack_and_rules.md` rule #8).

**Headline finding: the summary docx contains real, material inaccuracies**, caught by cross-checking its specific claims against the 3 primary-source PDFs directly (not taken at face value) — most notably, its opening "88% Italy vs 42% India, documented in the literature" framing doesn't trace to any paper it cites (the closest real number, Paul et al., is 0.838/0.729) and is suspiciously close to this project's own reported figures. Full breakdown, including a mischaracterized DCGAN claim and an overstated ViT domain-shift claim, in the report's "Source Reliability" section. The report itself is built from the primary sources directly, with every claim labeled `[Verified]` (read directly in the PDF) or `[Docx only]` (not independently checked).

**Major, well-verified finding: Ramos-Soto et al. (Scientific Reports, 2025) uses the exact same Eyes-Defy dataset as this project** (217/218 images, India 95, Italy 122/123) and applies real country/gender-specific thresholds (India F<12.0/M<14.0, Italy flat<10.5) — the **same numbers** this project's classification module considered and rejected early on as "unsourced" (see the "Two decisions resolved before any code was written" section above). They do have a real source after all; the earlier check was only against the dataset's own documentation, not the broader literature.

**But empirically, on our own data, those exact thresholds make our imbalance worse, not better** — computed directly, not assumed: current WHO thresholds give a 52.7pp India/Italy anemic-rate gap; Ramos-Soto's thresholds widen it to 74.1pp; Paul et al.'s alternative (flat <11.0 g/dL, both countries) narrows it to 30.6pp. **No threshold change has been adopted** — this is documented as an evaluated-and-computed option, not a decision, pending project-author input.

**Other findings that don't touch the label definition, ranked by directness:**
- Only one paper (Paul et al.) actually reports a stratified India-vs-Italy accuracy split, and it shows nothing close to a severe collapse (0.729 India / 0.838 Italy within-country; 0.733–0.844 even under true cross-country transfer with no retraining) — attributed to HSV+CLAHE illumination normalization plus a compact handcrafted feature set (not raw CNN pixels).
- CORAL (Correlation Alignment) domain adaptation is real and effective in that paper, but was only applied cross-*dataset* (Eyes-Defy→Ghana), not for India vs. Italy specifically, since that gap wasn't severe enough to need it in their pipeline. Applying CORAL specifically to the within-Eyes-Defy India/Italy split is a genuine, untested-in-this-literature idea worth prototyping here.
- `sensitivity`/`specificity`/`balanced_accuracy` as headline metrics (not raw accuracy) is independently argued for by Paul et al., for the same reason this project already added them to `compute_metrics()` last session.
- This project's existing augmentation choice (flip + rotate, no color jitter) is independently validated by Ramos-Soto et al.'s identical reasoning (color jitter would distort the diagnostic chromatic signal itself).

## Deeper threshold analysis: WHO vs. Paul et al.'s flat 11.0 g/dL (2026-07-28)
Follow-up to the finding above, prompted by the project author asking for a direct recommendation. Computed (not assumed) on the real train split and full metadata:

- **Paul et al.'s own stated justification ("less boundary noise") does not hold for India specifically.** 11.0 g/dL sits only 0.47 g/dL from India's own mean Hgb (11.47) — borderline-patient density (within ±0.5 g/dL of the cutoff) actually *increases* for India under this scheme (16.8%→20.0%), the opposite of the intended effect. It does work as intended for Italy (9.0%→4.1%, since 11.0 sits 2.83 g/dL from Italy's mean).
- **`pos_weight` (computed on the real 151-patient train split) jumps from 1.397 (WHO) to 3.314 (Paul)** — a much more aggressive positive-class upweighting, driven by positives shrinking from 63→35 train patients. This directly risks amplifying the exact `pos_weight`-driven "blanket-predict-anemic" collapse already documented across the original 6 models — a real, concrete downside specific to this project's known failure mode, not just a generic concern.
- **The label-rate gap narrowing (52.7pp→30.6pp) does not cleanly mean "less shortcut-learning risk."** Under WHO, each country's own-majority-class shortcut ceiling is high but points in *opposite* directions (India 71.6% always-anemic, Italy 81.1% always-non-anemic) — a country-correlated shortcut. Under Paul's scheme, India's majority *flips* to non-anemic (ceiling drops to 57.9%, genuinely less exploitable — a real win for India's signal-to-noise ratio) but Italy's ceiling rises slightly (81.1%→88.5%), and critically the **global pooled "always predict non-anemic" ceiling rises from 58.1% to 75.1%** — the risk shifts from a country-correlated shortcut toward an even-easier single-class shortcut, not away from shortcut-learning generally.
- **Verdict given to the project author: not clearly better for this dataset**, despite having a real, legitimate use case (narrowing India's own internal imbalance specifically). The clinical-interpretability cost (11.0 g/dL is not a validated adult anemia threshold — Paul et al. borrowed it from a pediatric convention for cross-*dataset* comparability, not because it's the correct adult cutoff) and the risk of worsening the already-documented `pos_weight` collapse mode outweigh the label-rate-gap improvement on current evidence. **This is a labels-only statistical analysis, not a trained-model comparison** — the only way to settle it definitively is to actually train identical pipelines under both schemes and compare held-out results, which hasn't been done.

**FINAL DECISION (2026-07-28): staying with WHO thresholds (M<13.0, F<12.0), no alternative threshold will be adopted.** Project author confirmed this after reviewing the full comparative analysis above. The threshold question is now closed, not just "no change yet" — any future revisit should be treated as reopening a settled decision, not a default next step. `prepare_dataset.py`'s `WHO_THRESHOLDS = {"M": 13.0, "F": 12.0}` (line 75) is unchanged and will not be touched by the v2 expansion or any batch-1/batch-2 Kaggle work.

## Two real bugs/findings caught during fresh implementation (not assumed correct)
1. **`.convert("RGB")` alone does NOT give a clean black background.** Verified empirically: the raw crop's "transparent" (alpha=0) region has mean RGB ≈36 at native resolution, not ≈0 — real leftover pixel data, not pre-zeroed. The root project's near-zero measurement (`CLAUDE.md` §1.2, mean RGB ≈0.0000165) turned out to be a side-effect of Phase 0's own Lanczos resize being alpha-premultiplied, not a property of the source file itself — confirmed by replicating Phase 0's exact pad+resize sequence on the same raw file and reproducing the same near-zero number. **Fix used here:** an explicit `Image.alpha_composite` onto a solid black RGBA canvas before dropping the alpha channel — verified to give an exact 0.0 mean / 0 max in the transparent region, robust and not dependent on resize-algorithm side effects.
2. **Typo-tolerant crop-file matching was necessary, and the first version missed a case.** `Italy/95`'s files are spelled `..._forniceal_palplebral.png` / `..._palplebral.png` (an 'l' swap), which a literal `"forniceal_palpebral" in filename` substring check silently misclassified as a plain forniceal-only file — the patient would have silently lost its forniceal_palpebral crop with no error. Fixed by matching Phase 0's own robust approach: the one PNG *without* "forniceal" in the name is always palpebral (spelling-independent), and among "forniceal"-containing PNGs, the longer filename is always the combined view. Added a self-check that raises on any folder with an unexpected count of forniceal-related files (not 0 or 2), so a *third* undiscovered spelling variant would surface loudly instead of silently misclassifying again. Re-ran after the fix: 211/217 forniceal_palpebral extractions succeeded, exactly matching the 6 folders (`Italy 1, 35, 54, 58, 75, 109`) the dataset's own documentation says lack an exposed forniceal conjunctiva — no other silent failures.

## Training engine design choices
- All 3 backbones (ResNet18, MobileNetV3-Small, EfficientNet-B0) are **frozen except the replaced single-logit head** — a first-version, not-yet-fine-tuned choice given only ~151 training patients (real overfitting risk with full end-to-end fine-tuning at this scale).
- `BCEWithLogitsLoss` with `pos_weight` computed per-trial from the train split's actual class ratio — addresses the mild (~1.4:1) raw label imbalance.
- Evaluation metrics (accuracy/precision/recall/F1/AUC) are computed **both in aggregate and stratified by India vs. Italy**, every epoch, printed and persisted to the study summary JSON — this is the primary defense against the country-confound shortcut-learning risk, not an afterthought metric.
- 12 Optuna trials per (architecture, tissue_type) combination, tuning `learning_rate` and `weight_decay` — matches the trial-count reasoning already established for the segmentation phase's aligned-dataset runs (enough trials to not be pure luck-of-the-draw, without exploding GPU/wall-clock cost for a first pass).

## Currently implemented evaluation surface (updated 2026-07-18, thesis-grade upgrade)
- **Loss:** `BCEWithLogitsLoss` with `pos_weight` computed per-trial from the train split's class ratio.
- **Performance metrics**, computed every epoch via `compute_metrics()` (`sklearn.metrics`): accuracy, precision, recall, F1, ROC-AUC, confusion matrix (`labels=[0,1]`, always a full 2x2 even if one class is absent from a slice), and ROC curve data (fpr/tpr) — all computed **both in aggregate and stratified by country** (India/Italy). Only the "overall" ROC curve is ever plotted (matching the literal request, which stratified the confusion matrix but not the ROC curve); per-country fpr/tpr is still computed and saved in the JSON as a low-cost byproduct of the existing per-country loop, not discarded.
- **Per-epoch history is now persisted**, closing the previous gap: `train_loss_history`/`val_loss_history` (plain float lists) are appended every epoch and stashed via `trial.set_user_attr()` on **every** trial (small enough not to matter for the trials CSV — this is not the "clutter" the plotting constraint below is about).
- **Plots — generated and saved ONLY for the single best trial per model** (`study.best_trial`, read once inside `_save_outputs()` after `study.optimize()` finishes), never per-trial:
  - `{model_name}_loss_curve.png` — train vs. val loss over epochs.
  - `{model_name}_roc_curve.png` — overall ROC curve with AUC annotated (skipped with a printed message if the best trial's val set somehow had only one class present — not expected with 33 val patients, defensive only).
  - `{model_name}_confusion_matrices.png` — 3-panel (overall/India/Italy) stratified confusion matrix, the primary confound-monitoring artifact.
  - Saved to `classification/outputs/plots/` (new directory, not gitignored — small PNGs, same "citable artifact" status as `outputs/logs/`, not `outputs/checkpoints/`).
- **Study summary JSON** (`{model_name}_study_summary.json`) now also includes a `plot_paths` dict pointing at the 3 saved images, alongside the existing `best_val_metrics_by_country` (which now carries confusion_matrix + roc_curve nested in each of overall/India/Italy).
- `matplotlib` added as a dependency (already present in the shared venv, no install needed) — forced to the `"Agg"` headless backend, since this code also needs to run on a Kaggle container with no display.

**No single winner recommended.** EfficientNet-B0/forniceal_palpebral for raw performance, MobileNetV3-Small/forniceal_palpebral if the thesis wants to highlight confound-robustness — these disagree, and that disagreement is itself worth reporting rather than collapsing to one number.
