## 9-architecture pretrained sweep × 2 tissue types (2026-08-08)
Requested by the project author to mirror classification's "9 models, compare on metrics" structure. Full roster/rationale in the approved plan; this records what was actually built and verified this session.

**New data engineering — `forniceal_palpebral` aligned segmentation dataset (did not exist before today):**
- `scripts/build_aligned_dataset_forniceal.py` — reuses the palpebral pipeline's SIFT/ORB+RANSAC algorithm unchanged (`find_homography_alignment`, `_alpha_is_functional`, `_white_background_mask` all copied verbatim), pointed at the second crop via a new `find_forniceal_crop_file()` (ported from `classification/datapreparepipeline/prepare_dataset.py`'s `find_crop_files()`, adapted to read zip entries directly rather than an extracted folder).
- **Result: 211/217 aligned, 0 genuine alignment failures.** The 6 exclusions are all "no forniceal_palpebral crop exists for this patient" (Italy_001/035/054/058/075/109) — matches classification's independently-documented list exactly, a strong cross-check. Area ratio to the raw photo is remarkably tight (13.73–14.03×, essentially no variance) — stronger geometric-consistency evidence than the palpebral pipeline had. All 211 via SIFT; inliers 66–2379 (mean 911.2, notably higher than palpebral's 312.5 mean, consistent with more texture in the wider crop). 29 of the 211 use the white-background mask fallback (`CLAUDE.md` §1.4.4's bug class), matching classification's own independently-found count of 30/211 almost exactly (off by one due to one patient's crop having no alpha channel at all, counted as "no alpha" not "white_bg" here — not re-investigated further, immaterial to the result).
- Visually spot-checked (India_071, India_002 [weakest inlier, 66], Italy_022 and Italy_004 [white-bg fallback cases]) — all 4 show the mask correctly covering the lower everted eyelid conjunctiva. New notebook `notebooks/verify_forniceal_alignment_sanity_check.ipynb` (mirrors the existing palpebral sanity-check notebook) built and executed clean: 0/211 blank masks, 0/211 near-blank. **Full human visual review still recommended before trusting this for training** — same gate this project has applied to every prior alignment pipeline.
- `AlignedConjunctivaSegmentationDataset` (`scripts/dataset.py`) generalized with a `tissue_type: str = "palpebral"` param (default reproduces prior behavior byte-for-byte; new `"forniceal_palpebral"` value resolves to the new dataset) rather than duplicated into a second class. Verified via `dataset.py`'s own self-test: palpebral counts unchanged (143/27/31), forniceal_palpebral = 147/31/33 (211 total).

**`trainer_engine.py` extended, not replaced:** new `build_model` (zero-arg model factory, used instead of `model_cls(in_channels=3, out_channels=1)` when given), `image_size`, and `tissue_type` params on `make_objective`/`run_study` — all optional. Several land slightly outside their originally-requested tier (e.g. ConvNeXt-Large at 203M vs. a 200M cap, CoAtNet-0/2 both ~3–8M over) — reported as measured, not forced to fit via arbitrary decoder-channel tuning.

**TransUNet implementation note (deliberate deviation from "vendor a package"):** no well-maintained PyTorch package exists for this architecture (the `transunet` PyPI package has only 3 releases, unverified quality). Built instead as a faithful composition of two independently pretrained, actively-maintained `timm` components — a ResNet50 (`features_only=True`) for multi-scale CNN features/skip connections, and a ViT-B/16's 12 transformer blocks + final norm (not its patch_embed or head) reused for global context over the bottleneck feature map, with the ViT's own positional embeddings bilinearly interpolated to the actual bottleneck grid size — plus a hand-written CUP-style decoder. Worked correctly on the first structural test (120.9M params, correct output shape) and passed its dry run.

**18 entry-point scripts** generated in `scripts/train_pretrained/` (mechanically, via `_generate_scripts.py`, mirroring classification's own generation precedent) — one per (architecture × `{palpebral, forniceal_palpebral}`), all `py_compile`-verified. `model_name = f"{arch_key}_{tissue_type}"` drives all checkpoint/log naming, distinct from every existing name.

**New dependencies** (shared root `requirements.txt`/`venv/`, no per-module isolation): `segmentation-models-pytorch==0.5.0`, `timm==1.0.28`, `transformers==5.14.1`, `einops==0.8.2` — all installed and confirmed compatible with Python 3.14.6 / `torch==2.13.0+cu130` (no wheel-availability issues found). **`requirements.txt` itself not yet regenerated via `pip freeze`** — flagged to the project author rather than done automatically, since the shared venv has accumulated unrelated packages (FastAPI, python-pptx, markitdown...) from other work in this repo (the deployment app), and a blind `pip freeze` would mix those into the training environment's requirements file.

**Real hardware constraint found (not a bug):** running all 9 builders sequentially in one local process hit a CUDA OOM on the local RTX 4050 (6GB) — a GPU-memory-carryover artifact of testing multiple heavy models back-to-back in one process, not a production concern, since each of the 18 real entry-point scripts runs as its own separate process/notebook cell on Kaggle (T4×2, 16GB per GPU). Still worth watching on Kaggle for the heaviest combos (Swin-Large at 512×512, batch_size=16) — if it OOMs there too, reduce `BATCH_SIZE` for just those combos rather than globally.
