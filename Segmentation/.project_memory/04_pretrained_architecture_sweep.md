**TransUNet implementation note (deliberate deviation from "vendor a package"):** no well-maintained PyTorch package exists for this architecture (the `transunet` PyPI package has only 3 releases, unverified quality). Worked correctly on the first structural test (120.9M params, correct output shape) and passed its dry run.

## Expanded evaluation metric set for thesis defense (2026-08-08, project author's explicit request)
Original metric set was Dice + IoU only. Project author asked for a broader set specifically to defend the thesis with; all 5 suggested additions implemented and verified via a real dry run (not just read/reasoned about):

1. **Precision/Recall** — added to `evaluate()`'s per-epoch validation (cheap, vectorized via the same TP/FP/FN decomposition Dice/IoU already used). Tracked in Optuna trial user_attrs (`best_val_precision`/`best_val_recall`, from the same best-Dice epoch as `best_val_iou` already was) and in the study summary JSON.
2. **Hausdorff Distance (HD95)** — new `Segmentation/scripts/segmentation_metrics.py`, `compute_hd95()` (scipy `distance_transform_edt` + `binary_erosion`, symmetric 95th-percentile, NaN — not a sentinel value — when either mask is empty). Deliberately **not** computed every epoch (per-image, not batch-vectorizable, meaningfully more expensive than Dice/IoU/Precision/Recall) — computed once, at the end of `run_study()`, on the final TEST-set pass only.
3. **Params + inference latency** — new `count_parameters()`/`measure_inference_latency()` in `trainer_engine.py`, measured once per model on a fresh (untrained) instance (architecture property, not hyperparameter-dependent), GPU-synchronized timing with warmup. Saved in the study summary JSON (`n_params`, `inference_latency_ms_batch1`).
4. **Paired significance testing** — new `Segmentation/scripts/compare_models_significance.py`. Paired Wilcoxon signed-rank test + paired bootstrap 95% CI on a chosen metric, over patients common to both models' per-patient CSVs; "significant" requires **both** tests to agree (deliberately conservative). Directly motivated by classification's own `step1_cv_harness` lesson (small test sets → point-estimate rankings can be pure noise).
5. **Country-stratified metrics** — `country_stratified_summary()` in the same new script; per-country + overall mean of every metric, ties into the project's existing India/Italy confound narrative (CLAUDE.md Sec 0.5).

**Methodological fix that fell out of doing this properly:** `run_study()` previously only ever evaluated on the **validation** split (used for both early stopping and checkpoint selection). Reporting those same numbers as final results would be a form of selection bias. `run_study()` now also runs a genuine final evaluation on the held-out **test** split (`segmentation_metrics.evaluate_final_test_set()`, one patient at a time, batch_size=1, for simple correct patient_id bookkeeping) using the actual saved best checkpoint — this is what feeds items 2, 4, and 5 above. A new per-model CSV, `outputs/logs/{model_name}_test_per_patient.csv`, is saved specifically so per-patient granularity survives for the significance test (an aggregate-only summary can't support that).

**Verified via two real dry runs** (`cnn_base_efficientnet_b1_unet` and `hybrid_base_coatnet0_unet`, both palpebral, 1 trial/1 epoch each, through the actual unmodified `run_study()` — not a hand-simulated check): precision/recall printed correctly every epoch; params measured exactly right (8,757,105, matching the already-known figure); latency measured (16.85ms); final test-set eval ran cleanly on all 31 test patients, 0 with undefined HD95; per-country breakdown correct (13 India / 18 Italy). Then ran `compare_models_significance.py` against both dry runs' real output — correctly computed a country-stratified table for each model and a paired comparison whose two significance tests disagreed at the margin (bootstrap CI excluded zero, Wilcoxon p=0.053), correctly resolving to "not significant" under the conservative combined rule — a genuine edge case, not just a happy-path pass. All dry-run artifacts (checkpoints, logs, comparison CSVs) deleted afterward, per this project's standing convention.

**Kaggle notebook updated to match:** `scipy` added explicitly to the pip-install cell (previously relying on it being scikit-learn's own transitive dependency on Kaggle's base image — true almost certainly, but now stated rather than assumed, since it's a real load-bearing dependency now). No other notebook changes needed — the new metrics live entirely inside `trainer_engine.py`, inherited automatically by all 18 entry-point scripts with zero changes to them.

**Not yet done:** `compare_models_significance.py` has only been exercised against dry-run (1-epoch) data — its real use (comparing actual trained models) waits on real Kaggle results existing.

## Plots added; Kaggle output now weights + plots + values, one downloadable zip (2026-08-08, project author's explicit request)
Until now `trainer_engine.py` only ever wrote raw numbers (JSON/CSV) — no charts at all. New `Segmentation/scripts/segmentation_plots.py`, called once at the end of every `run_study()` (inside `_save_outputs()`), writes 5 PNGs per model to the new `Segmentation/outputs/plots/` directory (tracked in git, not gitignored — same convention as `outputs/logs/`, nothing in `.gitignore` needed changing since no existing pattern would have caught this new folder):

- `{model_name}_training_curves.png` — train/val loss + val Dice/IoU/Precision/Recall vs. epoch, **best trial only** (per-epoch history is now recorded via `trial.set_user_attr("epoch_history", ...)` inside every trial in `make_objective`, then read back from `study.best_trial.user_attrs` afterward — this history-tracking didn't exist before today).
- `{model_name}_loss_fn_comparison.png` — mean/best Dice per loss_fn (bce_dice vs focal_tversky) across all trials.
- `{model_name}_test_summary.png` — final test-set Dice/IoU/Precision/Recall (one panel) + HD95 (separate panel, different units).
- `{model_name}_test_by_country.png` — same test-set metrics, grouped by country.
- `{model_name}_test_per_patient_dice.png` — box + jittered-point plot of per-patient test Dice, by country (shows variance, not just the mean).

**Real bug caught by actually running it, not just reading the code:** first dry run crashed — `ax.boxplot(..., labels=countries)` used matplotlib's old kwarg name, which was fully removed in the locally-installed matplotlib 3.11 (renamed to `tick_labels` partway through the 3.x series). Fixed by setting tick labels via `ax.set_xticklabels()` afterward instead of relying on either spelling of the boxplot-native kwarg — deliberately version-agnostic, since Kaggle's matplotlib version isn't known in advance and a fix that only worked for the newer spelling would just move the same failure mode to whichever environment has the older matplotlib.

**Verified via two full dry runs** (one crashed on the bug above, the fix was verified by re-running the same combo): confirmed all 5 PNGs are written with the expected filenames, and visually inspected two of them (`test_by_country`, `test_per_patient_dice`) — both render correctly (grouped bars split by country, correct axis scales/units, box plot with mean marker and jittered points). All dry-run artifacts (checkpoints, logs, plots) deleted afterward.

**Kaggle notebook (`segmentation-pretrained-sweep.ipynb`) updated to match:** `sync_outputs()` now also collects `Segmentation/outputs/plots/` into the consolidated `/kaggle/working/outputs/` folder and the downloadable zip, alongside checkpoints and logs — this is what actually delivers "weights + plots + values, one zip" end-to-end on Kaggle, not just locally. No other notebook changes needed.
